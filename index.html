# 做T涨幅计算器 · 工程交接说明 ## 这是什么 一个单文件 H5 计算器，用来算 A 股「一轮买入 + 卖出」的打平涨幅（即股价至少要涨多少才不亏），已处理"单笔佣金不足 5 元按 5 元收取"的真实约束。 面向散户做 T 的成本测算场景，移动端优先设计（微信内可直接打开）。 ## 文件清单 | 文件 | 说明 | | --- | --- | | `做T涨幅计算器.html` | 唯一产物。单文件自包含，HTML + 内联 CSS + 内联 JS，零外部依赖，双击即可在浏览器打开 | | `README.md` | 本说明文件 | 无 `assets/`、无 CDN 引用、无构建步骤、无网络请求。 ## 已发布地址 - 线上链接：https://bytedance.doubao.link/app/app_17hk9f0r017 - app_id：`app_17hk9f0r017` - 如需重新发布到同一应用，在该 HTML 所在目录执行： `lark-cli apps +deploy --file-path ./做T涨幅计算器.html --app-id app_17hk9f0r017` ## 核心公式 ``` n% = max(2x, 10/(y·P)) + (s + 2g) ``` | 符号 | 含义 | 单位 | | --- | --- | --- | | x | 佣金费率 | %（填 0.023 表示万分之2.3） | | y | 手数（1手 = 100股） | 手 | | P | 股价 | 元 | | s | 印花税率 | % | | g | 过户费率 | % | | n | 打平所需最低涨幅 | % | ### 推导 - 单边成交金额 `A = 100·y·P` - 单笔佣金 `max(A·x/100, 5)`，买卖两笔 - 印花税仅卖出：`A·s/100` - 过户费双向：`2·A·g/100` - 令毛利 `A·n/100` 等于总成本，两边除以 `A` 得 `n = 2·max(x, 500/A) + (s + 2g)`，即 `max(2x, 10/(y·P)) + (s + 2g)` ### 关键派生量 - **脱离 5 元收费区的手数门槛**：`y_min = 5/(x·P)`（手） - **每股需涨金额**：`ΔP = P·n/100` - **卖出目标价**：`P·(1 + n/100)` ## 页面功能 输入：股价、手数、佣金率、印花税、过户费（后三个带默认值 0.023 / 0.05 / 0.001）。 输出： - 打平涨幅 n%、每股需涨金额、对应卖出价 - 成交金额、佣金、印花税、过户费、合计成本明细 - 是否落在 5 元最低收费区的判定，以及脱离所需手数 - 1 / 5 / 10 / 20 / 30 / 33 / 50 / 100 手的对照表 - 快捷手数按钮（点击直接填入） ## 已验证算例 参数：P = 6.66 元，x = 0.023%，s = 0.05%，g = 0.001%。门槛 `y_min = 5/(0.023×6.66) ≈ 32.6` 手，即 33 手切换。 | 手数 | 打平涨幅 | | --- | --- | | 1 | 1.554% | | 5 | 0.352% | | 10 | 0.202% | | 20 | 0.127% | | 30 | 0.102% | | 32 | 0.099% | | 33 | 0.098% | | 50 | 0.098% | | 100 | 0.098% | 33 手时单边成交额 21,978 元、总成本约 21.54 元、每股需涨约 0.0065 元（跳 1 分即够）。 ## 需要注意的口径 1. **x 的单位是百分数**，填 0.023 而不是 0.00023。 2. 算出来的是**打平线**，不是"值得做"的线。实盘建议在其基础上留 0.2 个百分点以上的缓冲。 3. 结果为理论税费成本，**不含滑点、盘口买卖价差、冲击成本**。 4. 公式忽略二阶项（卖出金额比买入高 n% 带来的微量费用差），误差量级约 0.00005%，可忽略。 5. 印花税率、过户费率做成可改参数，是因为政策可能调整，不要把 0.05 / 0.001 写死。 ## 技术约束（若要修改） - 单文件自包含：CSS 写在 `
